全対応後の内部構造 表示忠実度とDiff網羅性を同じ土台にする

現在すでにdrawing・page setup・data validationをJSZip直読で補う経路がある。その方針をパッケージ全体へ拡張し、表示用データと意味比較用データを分離する。

01

Package inventory

OPC relationshipsを辿り、本文・Story・style・drawing・表・Pivot・コメント・保護・外部要素の存在を列挙。

02

Dual model

実効表示を持つrender modelと、raw値・式・参照・構造・metadataを持つsemantic modelを生成。

03

Normalized diff

rIdやstyle IDをそのまま比較せず、scope・位置・内容fingerprintで正規化。内容/書式/構造/注釈へ分類。

04

Honest presentation

描画、代替表示、対応範囲外を区別。画面上の印と変更一覧を相互ナビゲーションし、打切り・省略理由も表示。

継承する現行資産。 Excelの絶対見出し、HLS tint/indexed色、入力規則正規化、行LCS、図形/改ページDiff、エラー通知、Wordの段落・文字LCS、書式ツールチップ、ゴースト、ズーム・ナビ・世代管理は捨てず、新しい意味モデルの表示先として利用する。
