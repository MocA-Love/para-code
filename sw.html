Para Code Mobile / multi-PC switch

iPhone 案Aドロワー上部のPCカード → 切り替えシート

いまの「接続中のPC」カードをそのまま押せる行にする。タップでボトムシートが立ち上がり、ペアリング済みPCが縦に並ぶ。既存レイアウトを一切崩さず、PCが1台のときは今と同じ見た目のまま（シートを開いても1行＋追加のみ）。

効く点「PCの情報が出ている場所＝PCを替える場所」で迷わない。台数が増えても縦に伸びるだけで破綻しない。1台運用の人の画面は今と変わらない。
引っかかる点切り替えに2タップ（ドロワーを開く＋カード）。頻繁に往復する使い方だと案B/Cより遅い。

iPhone 案Bドロワー最上部の横並びPCレール

ドロワーの一番上に、ペアリング済みPCのチップを横一列で常設する。1タップで切り替わり、シートもポップオーバーも挟まない。チップの赤バッジがそのまま「裏のPCで待たれている件数」になる。

効く点切り替えが最短（ドロワーを開いて1タップ）。全PCの状態が常に見えるので、切り替えるべきかの判断が要らない。
引っかかる点PCが1台でもレールぶんの高さを取る（1台なら隠す条件分岐が要る）。4台を超えると横スクロールになり、端のPCが隠れる。

iPhone 案Cヘッダーのチップを長押し → ポップオーバー

ドロワーを開かずに、いまの画面のままPCだけ替える。ヘッダー左のワークスペースチップに小さなPCの印を重ね、長押しでPC一覧のポップオーバーを出す。案A・案Bと排他ではなく、上乗せできる近道。

効く点どのタブからでも最短で替えられる。ドロワーを開く動作が要らない。
引っかかる点長押しは発見されにくい（単独では成立せず、案A/Bのどちらかと併用が前提）。チップにPCとワークスペースの2つの意味が乗る。

iPad 案Dサイドバーの左に常設のPCレール（3カラム）

iPadは幅に余裕がある。既存の常設サイドバーの左へ62ptのレールを足し、PCを縦に並べる。ワークスペースの階層（PC → ワークスペース → エージェント）が左から右へそのまま並ぶ。

効く点全PCが常に見えて1タップ。iPadでの「複数マシンを並行で回す」使い方に一番合う。既存の2カラムはそのままで、左に足すだけ。
引っかかる点本文の幅が62pt減る。Split View（狭い幅）ではレールを畳んで案A相当に落とす分岐が要る。

iPad 案Eサイドバー上部のPCカード → ポップオーバー

iPhone案Aと同じ考え方をiPadへ持ってきた形。カードをタップすると、そのカードを起点にポップオーバーが降りる。レールぶんの幅を取らず、iPhoneとiPadで操作が完全に同じになる。

効く点iPhoneと同じ操作・同じ部品。本文の幅が減らない。狭い幅（Split View）でも同じ見せ方のまま通せる。
引っかかる点他PCの状況が開くまで見えない（カード右のバッジで補う必要がある）。iPadの広さを活かしきれない。

共通設定 → PCの管理

どの案を採っても必要になる管理画面。名前の変更（PCから名前が届かない旧バージョン向けにも要る）、並び替え、1台ずつのペアリング解除、そして「裏のPCからの通知をどこまで受けるか」をここに置く。

この検討の前提（実装調査より）
リレーはPC（deviceId）ごとに独立していて、モバイル1台が複数PCへ同時に繋ぐこと自体はリレー・PC側の変更なしで成立する。モバイル側は資格情報を1件だけ持つ作り（para.credentials 1キー、コントローラ1本）なので、そこを配列化するのが主な作業。
アプリ未起動時のプッシュ通知だけは追加対応が要る。復号鍵をPCごとに保存し、通知拡張が鍵を順に試す形に変える（PC名を通知本文に出すのも同じ変更の中でできる）。
ピン留め・アーカイブ・下書きなど端末ローカルの記録はターミナルIDだけをキーにしているため、PCをまたぐと衝突する。キーにPCの識別子を足す必要がある。
