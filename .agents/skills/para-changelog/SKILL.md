# Para Code の更新履歴の書き方

書く場所と運用（いつ書くか、`## 未リリース` の確定、ベータでは改名しない、モバイルの版と `app.json` の一致）はリポジトリの `CLAUDE.md` の「更新履歴（アプリ内changelog）の運用」に従う。ここには「1 行をどう書くか」だけを書く。

## 一番大事なこと

利用者が読んで「何ができるようになったか・何が直ったか」が分かる 1 文だけを書く。経緯・原因・仕組み・手順は書かない。詳しいことは PR の本文に書く。

## 決まり

1. 1 項目 1 文。おおむね 60 字、上限 80 字（`` ` `` と `**` の記号は数えない）。
2. 文末: 新機能は「〜できるようになりました」「〜ようになりました」、修正は「〜を直しました」。改善は「〜ようにしました」か、変えた結果の動詞（そろえました・まとめました・畳みました）で終える。
3. 原因・経緯・「これまでは〜でした」・「〜のため」を書かない。
4. 操作の手順・キー・上限の数値・例外の条件は書かない。入口の名前（画面やボタンの名前）は 1 つ残してよい。
5. 内部の動き・ファイルのパス・クラス名・仕組みの用語（hook の中身、IPC、worker、プロセスの名前など）を書かない。ただし、利用者の設定ファイルを自動で書き換えることは、触るファイルが分かる形で残す。
6. コマンド名・設定名は利用者が触るものだけ `` `コード` `` で残し、1 項目に 1 つまで。
7. 同じ版の同じ機能は 1 行にまとめる。80 字に収まらなければ、その機能の中で 2〜3 行に分ける。逆に、1 項目に別の機能や直しが詰まっていたら分ける（行が増えてよい）。
8. 利用者に見えない直し（内部の整理、テスト、計装、ビルド）は書かない。ただし、利用者のデータを外へ送る・送る中身を変えたこと（メモリ使用量の内訳を送る、エラーの報告に含めるもの）は、画面に出なくても 1 文で残す。版の項目が全部無くなったら、見出しと日付は残し「- 目に見える変更はありません。」の 1 行を置く。
9. 入れ子の箇条書き・表・地の文・リンクを書かない。アプリの画面は `- ` で始まる行しか出さない。
10. 節は `### 新機能` → `### 改善` → `### 修正` の順に 1 回ずつ。項目の無い節は作らない。PC の md に入れるモバイルの項目は、その種類の節に入れて「モバイルで、」から書き出す。使い方が変わる知らせ（既定が変わった、既定の一覧から外した）は `### 改善` に入れる。
11. 太字は 1 版に 1 か所まで。その版の目玉だけ。
12. 見た目の細かい直しは画面の名前を並べ、並べきれない分は「ほか N か所」と数で書く。「など」で濁さない。
13. 製品名・版番号・モデル名・キーの名前は元のまま写す。丸めない。
14. モバイル（`MOBILE_CHANGELOG`）: `title` は 1 文 60 字まで。`body` は原則なし。操作が要るときや結果が変わるときだけ 1 文 40 字まで。
15. モバイル: `tone` は新機能＝書かない（accent）、改善・修正＝`green`、利用者の操作が要る＝`yellow`。`body` が「PC の Para Code の更新が要ります。」の項目も `yellow` にする。`purple` は使わない。`icon` はその行の主の機能のもの。`headline` はその版の目玉があるときだけ。

このほか、ユーザーの `~/.claude/CLAUDE.md` の「文章の書き方」（です・ます、常套句と翻訳調を使わない、ダッシュの挿入句を使わない、比喩を使わない）を守る。

## 例

| 悪い例 | 良い例 |
|---|---|
| 内蔵ブラウザの Chrome 拡張機能のショートカットを付け替えられるようにしました。「設定」→「ショートカット」に…「変更」を押してからキーを押すと付きます（⌘・⌃・⌥ のどれか…）。✕ で外し… | 内蔵ブラウザの Chrome 拡張機能（試験的）のショートカットを付け替えられるようになりました。 |
| …「停止」を押しても止まらないのを直しました。停止の依頼が実際には送られる前に接続を切っていたためで、ログには… | 「常駐ターミナル」の「停止」で止まらないのを直しました。 |
| ⌘V で貼る・欄へドラッグする・クリップのボタンで選ぶの 3 つで、8 枚まで・1 枚 10 MB まで… | 「新しいスペース」の指示に画像を添えられるようになりました。 |
| 細かい見た目のずれを直しました。「ワークツリーを作る」の作成先のパスで先頭の / が右端に回っていたのを… | ワークツリーの作成先のパスやリモートホストの札ほか、表示のずれを 6 か所直しました。 |

## 書く前に確かめること

- その変更は利用者に見えるか（見えなければ書かない）。
- 同じ版に同じ機能の行が既にないか（あれば 1 行にまとめる）。
- 60 字を超えたら、手順・数値・原因・仕組みを書いていないか見直す。
- 文末が決まり 2 の形か。
